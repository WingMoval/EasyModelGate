# ADR-0002：数据库时间统一为 Unix epoch 毫秒（UTC）

- 状态：已接受（2026-08-26）
- 关联规格：§28 时间、§29 时区

## 背景

request_logs / api_keys / users / backends 都需要时间字段；
Analytics 需要按 hour/day/week/month 分桶且用户位于 UTC+8。

## 决策

1. 全部时间字段统一为 **Unix epoch 毫秒（INTEGER，UTC）**，全表全代码一致，不混用秒。
2. 选择毫秒的理由：TTFT / queue_wait 等 ms 级指标可直接整数存储，避免浮点；
   毫秒除以 1000 即可对接 SQLite datetime 函数。
3. 分桶时区转换不在 SQL 中硬编码偏移：由 Python `zoneinfo` 按配置
   （usage.timezone，默认 Asia/Shanghai）计算固定偏移量后注入 strftime 修饰符。
4. 存储永远 UTC；本地化只发生在查询输出层。

## 后果

- 正数毫秒可表示至公元 294247 年，无 2038 问题。
- 若未来出现跨夏令时时区（如 America/New_York），按区间中点取偏移的策略需要复核；
  v0.1 用户群（UTC+8，无夏令时）不受影响。
